# 培训内容包的试卷引用与交互变量采集接入约定

## 来源获取

获授权供应方网关 `/package` 返回文件目录、相对path、原始格式、修订号与href。GET `/raw/路径` 获得原始字节，ETag与内容绑定，条件请求304不带正文。legacy只开放第一项，feature开放完整本地资料；不需要访问真实机构或下载生产数据。目录不是完成性证明，文件可有503或404，源缺件和字段未决分别记录。真实格式范围以本文profile为准，不要求实现所引标准所有未使用扩展。

## 数据解释

QTI3命名子集，未列命名空间不影响本地样例；资源路径相对于引用者文件。输出是试卷内引用实例，id=testId:refId，每实例itemId=item-a，responses是所属题目内的变量声明和选择交互，不把RESPONSE提升为全库键。两次引用共享一个题目但仍是两个实例；stimulus来自相对路径，未取到材料时引用未决。可扩展自定义交互，将未知节点原样保存而非按普通选择题解析。不执行response-processing。

## 修订和补件

本地测试可用 `source.state.round=2` 驱动一次修订：共用题目选项A文字改为Choice A revised，不改变ref-1/ref-2身份。 `state.failDoc`、`state.missingDoc`可设为目录document.id，分别模拟临时失败与缺件，清空后恢复。采集端只能经HTTP观察，不允许读取source.state或fixture.expectedIds作为采集结果。fixture.expectedIds仅是公开验收对照。原始资料及解释版本需要可核对；失败不能使已确认内容凭空消失。把已取得的文件索引、源端修订、规范化记录及字段来源协同持久化；存储结构可扩展，不规定实现架构。

完整性至少区分取得文件与解释关系两个层次；已隔离的未知字段不能被称作已解释。notes为现有人工诊断入口，可扩展结构，但信息应包含具体资料位置和未决原因。文件级原始证据由Repository.retain保留。legacy的人工预览入口继续可用；managed模式负责结构化接入。

## 验证矩阵

1. 按样本跨文件完成 内容对象与引用实例分离 与 分节资源和相对URI，不以读取目录或预览摘要代替。
2. 对同一原始资料重复投递及重开存储，规范化身份不膨胀，来源证据仍可追溯。
3. 交互变量作用域 不因缺件或顺序改变而被默认值掩盖；补件后只重解释受影响对象。
4. 使用round=2比较新旧解释，说明 共用材料及未知交互留存 如何留痕。
5. 在原始资料已保存、关系尚未提交等边界终止进程，再启动能识别待完成工作；不得靠固定样本答案实现。

`acceptance/managed.test.mjs`仅覆盖关键正例及重启重投，改动时需按以上矩阵增加适合方案的异常和来源变化测试。资料未齐时保留可解释未决，不为“通过”填充不存在的源值。
